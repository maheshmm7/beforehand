# Code of conduct

## The short version

Be decent. Argue about the work, not the person. Assume the other reader is trying to get it right.

## What is expected

- **Criticise the code, not its author.** "This drops a deadline when the guest list shrinks" is a
  review. "Did you even read it?" is not.
- **Say what you mean, plainly, and then stop.** Directness is welcome here. Contempt is not, and
  the difference is whether the sentence could be acted on.
- **Assume competence.** Somebody who did it differently usually had a reason. Ask what it was
  before deciding there wasn't one.
- **Take correction well.** Being wrong in public is the normal cost of working in public.
- **Respect the time of whoever reads next.** An issue with the steps in it, a commit message that
  explains itself, a reply that answers the question asked.

## What is not

- Harassment, in the issues, in review comments, or anywhere else this project is discussed.
- Insults, slurs, or remarks about who somebody is rather than what they wrote — age, body,
  disability, ethnicity, sex characteristics, gender identity or expression, experience,
  education, socio-economic status, nationality, appearance, race, caste, colour, religion, or
  sexual orientation.
- Sexual language or imagery, and unwelcome attention of any kind.
- Publishing somebody's private information without their explicit permission.
- Sustained disruption: repeatedly reopening a settled decision, or arguing in bad faith.

## Scope

This applies in every space this project uses — issues, pull requests, discussions, commit
messages, and anywhere somebody is representing the project in public.

## If something goes wrong

Report it to the maintainer by opening an issue titled "Conduct report" with no detail in it, and
you will be given somewhere private to send the rest. If the report concerns the maintainer, say so
there; GitHub's own
[reporting tools](https://docs.github.com/en/communities/maintaining-your-safety-on-github/reporting-abuse-or-spam)
exist for exactly that case and using them is appropriate.

Reports are read in confidence. The maintainer may delete or edit comments, close an issue or a
pull request, or block an account, and will say that an action was taken without publishing the
report behind it.

This project is maintained by one person. The commitment here is that a report is read and acted
on, not that there is a committee behind it.
