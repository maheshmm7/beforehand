# Beforehand

**Know what a decision costs before you make it.**

A planning assistant for weddings, birthdays and community events. Every other planner is a
recorder: you decide, it stores. Beforehand is a simulator — change one thing and it shows you every
cost, deadline and task that change sets off, before you commit to it.

> This is a planning aid that works from estimates and from quotes you supply. It is not financial
> advice and it does not replace a professional planner, a caterer or a venue manager.

---

## The chosen challenge

Challenge 5: _"Create a GenAI-powered planning assistant that helps users organize weddings,
birthdays, and community events with budgets, timelines, vendor checklists, and personalized
ideas."_

Each of the four named artefacts is produced by the same engine rather than by four unrelated
screens:

| Required artefact  | How it is produced here                                                                                                  |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------ |
| Budgets            | Derived from the event model, never typed in. Every line is `estimated`, `quoted` or `paid`.                             |
| Timelines          | Decision deadlines computed from lead times and irreversibility, plus a run-of-show scheduled backwards from the anchor. |
| Vendor checklists  | Generated by the model, so it cannot omit something the plan implies. Each entry holds the vendor's own quoted wording.  |
| Personalized ideas | Suggested only from inside the feasible set, each with its cost ripple attached.                                         |

## The working principle

An event is a graph of coupled decisions. The engine holds:

- **variables** — the levers (guest count, venue class, menu tier, date);
- **quantities** — values derived from them (tables, households, out-of-town guests);
- **cost rules, constraints, tasks and lead times** — declarative data, evaluated by pure functions.

Changing a lever re-evaluates the graph and reports the **difference**: which lines moved, which
deadlines shifted, which tasks appeared, which constraint broke.

**Generative AI reads and proposes; it never does the arithmetic.** Gemini turns a free-text
description of an event into a structured model and suggests ideas within the constraints. Every
rupee is computed by ordinary TypeScript, so the numbers cannot be hallucinated and each one can
show its working. The core product also runs with no AI key configured at all.

## Running it

```bash
npm install
cp .env.example .env    # add a Gemini API key to enable the assistant
npm run dev             # the web app
npm run dev:api         # the API, in a second terminal
```

`npm run verify` runs the whole gate: types, lint, formatting, a secret scan, tests with coverage
thresholds, the production build, and a gzipped bundle budget.

## Architecture

- `src/` — React 19 front end, TypeScript in strict mode with `noUncheckedIndexedAccess`.
- `shared/` — schemas and the planning engine, shared by client and server.
- `server/` — Express 5 API: Helmet with a strict CSP, per-IP rate limiting applied before body
  parsing, a body size limit, `Cache-Control: no-store`, and stable error codes that never carry a
  stack trace.
- `api/` — a single serverless entry point that mounts the same app.
- `scripts/` — the secret scan and bundle budget used by `npm run verify` and CI.

The Gemini API key is read on the server only and never reaches the browser bundle.

## Assumptions

- Cost rules ship as hand-authored estimates for a small number of event types. They are a starting
  point to be replaced by real quotes, not a price guarantee.
- Plans are stored in the browser. There are no accounts, no passwords and no user database, which
  is a deliberate decision to keep the attack surface small.

## Limitations

This section describes what is in the repository today, not what is planned.

- The app is at the scaffold stage: brand, design tokens, the loading state, the API shell with its
  security middleware, and the verification pipeline. The planning engine and the interface are
  being built on top of it.
- Figures are estimates drawn from a hand-authored model, so they will not match local prices
  exactly.
